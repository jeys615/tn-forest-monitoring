## 7. Baseline Management & Sensor Track Isolation

- **Dual-Track Separation:** Optical baselines (`COPERNICUS/S2_SR_HARMONIZED`) and SAR baselines (`COPERNICUS/S1_GRD`) operate on completely isolated sensor tracks.
- **Active Invariant:** Exactly **one active Optical baseline** and **one active SAR baseline** are maintained per monitored zone.
- **Traceability:** Baseline documents store direct foreign keys to `SatelliteMetadata` (`imageId`, `source`, `acquisitionDate`, and full `zonalStatistics`).
- **Retirement Invariant:** Activating a new baseline automatically marks previous baselines for that sensor track as `RETIRED` with an immutable audit log.
- **Cross-Sensor Subtraction Prohibition:** Direct mathematical subtraction between Optical and SAR values is strictly blocked (`SENSOR_TRACK_MISMATCH`).

---

## 8. Temporary Area Isolation (M7 Invariant)

- **Isolation Guarantee:** Temporary area analysis and historical reference retrieval queries (`POST /api/baselines/historical-reference`) never create, mutate, or retire permanent zone baselines.
- **Scope Segregation:** Zonal reductions and image processing results for temporary areas maintain explicit `temporaryAreaId` scoping without touching permanent zone records.

---

## 9. Idempotency & Guaranteed Ephemeral Cleanup

- **Duplicate Acquisition:** Re-submitting an acquisition request for an identical date range and zone returns the existing `SatelliteMetadata` document without database duplication.
- **Duplicate Image Processing:** Re-processing an observation returns the existing `ProcessedImageResultDto` idempotently.
- **Zero Heavy File Persistence:** Raw 500MB GeoTIFF scene files are never downloaded or stored permanently. All spatial aggregations occur server-side in GEE.
- **Ephemeral Workspace Cleanup:** `TempImageManager.withTemporaryWorkspace()` guarantees total directory deletion in a `try ... finally` block under both normal execution and unhandled exception scenarios.
